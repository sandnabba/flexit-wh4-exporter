# Development

## How it works

The unit is controlled by a Siemens Climatix controller (`POS3.67`) that serves its data points as
standard BACnet objects (analog inputs, multi-state values and so on). Every object has an English
description, and multi-state objects have `stateText`, so [bacnet-objects.csv](bacnet-objects.csv)
is a better reference than the tables in the Flexit manual (which contain known errors).

The exporter uses [bacpypes3](https://github.com/JoelBender/BACpypes3). On each scrape it sends one
ReadPropertyMultiple request for the present value of every point. The controller accepts
1024-byte messages and splits larger responses into segments. It spends about 100 ms per request,
so one segmented request for all ~110 points (`--chunk-size 150`) is faster than splitting it.
Device information and the enum state texts are read once at startup and again after the unit has
been unreachable.

The unit has no history of its own (no trend-log objects), which is why the exporter exists.

### Code structure ([wh4_exporter.py](../wh4_exporter.py))

* [points.yaml](../points.yaml) drives everything: BACnet object → metric name, labels, `type`
  (gauge/counter/enum/bool) and `scale`. `load_points` enforces that points sharing a metric have
  the same type and label keys.
* `BacnetReader` owns a bacpypes3 `Application` in its own asyncio loop thread. The Prometheus
  client calls `collect()` synchronously from its HTTP threads and bridges into that loop with
  `run_coroutine_threadsafe`.
* `WH4Collector.refresh()` does one chunked ReadPropertyMultiple of every `presentValue`, cached
  for `--cache-seconds`.
* Enums are exported twice: `<metric>{state="<stateText>"}` 0/1 for every state, plus
  `<metric>_code`. Hours counters are scaled to seconds (`*_seconds_total`).

### bacpypes3 gotchas

All of these have bitten:

* Property names come back normalised (`present-value`, not `presentValue`), so look results up
  via `pid()`.
* Per-property errors come back as `ErrorType` values.
* A failed RPM is *returned* as `ErrorRejectAbortNack` (or `None`), not raised.
* Failing `read_property` calls raise bacpypes3 errors that are **not `Exception` subclasses**, so
  catch `BaseException` (but re-raise `CancelledError`/`KeyboardInterrupt`).

## Adding points

The unit exposes about 2000 BACnet objects. [bacnet-objects.csv](bacnet-objects.csv) lists all of
them with the controller's own names, descriptions, units and state texts, as read from a WH4. To
export another one, add a line to [points.yaml](../points.yaml):

```yaml
- {object: "analog-value,253", metric: dhw_setpoint_celsius, labels: {mode: comfort}, type: gauge}
```

`type` is `gauge`, `counter`, `enum` or `bool`. `scale` multiplies the value, for example 3600 to
convert hours to seconds. Points that share a metric name must have the same type and the same
label keys.

Verify the change against a unit with `--once`, and check that `wh4_point_errors` is 0:

```bash
.venv/bin/python wh4_exporter.py --target 192.168.1.50 --once | grep -E 'wh4_(up|point_errors)'
```

There are no automated tests.

### Reaching the unit from another network

Broadcast discovery is not needed, but the unit must be reachable by unicast UDP 47808. If you are
working from a machine that can't reach it directly, you can tunnel BACnet through a host that
can, then point the exporter at the local end of the tunnel and bind it to another loopback
address:

```bash
.venv/bin/python wh4_exporter.py --target 127.0.0.1:47808 --local-address 127.0.0.1/8:47809 --once
```

## Dashboard generator

The dashboard JSON is generated by [grafana/build_dashboard.py](../grafana/build_dashboard.py)
(uid `flexit-wh4`, with `datasource` and `instance` template variables so it imports anywhere).
Never edit the JSON by hand:

```bash
python3 grafana/build_dashboard.py grafana/wh4-dashboard.json
```

Things that matter:

* Every panel gets `pluginVersion` set. Without it Grafana runs the pre-11.1 xychart migration,
  which wipes the XY panel's `series` mapping (the panel shows "No data").
* The heating-curve XY panel joins A+B (outdoor/flow over time) by `Time` and C+D (curve points)
  by the `point` label, using transformations scoped with `filter: byRefId`.
* The state timeline uses static value mappings copied from the unit's `stateText`. Update
  `HP_STATE`/`PLANT`/`DHW`/`VENT`/`OPMODE`/`MAINT`/`HP_MAINT` if a unit reports other texts.
* Colours follow a fixed categorical order (`C[0..7]`). Status colours (good/warn/serious/
  critical) are only used for alarms and state. Avoid putting orange next to red or yellow in the
  same panel, and never use dual y-axes.
* PromQL that divides `wh4_operating_seconds_total{function=...}` by another series needs
  `ignoring(function)`.
* Use `suffix: h` / `suffix: rpm` units. Grafana's `h` auto-scales to years, and its `rpm` is not
  revolutions per minute.

## Local dev stack

[dev/](../dev/) has a local stack for working on the dashboard without a heat pump. A fake exporter
replays [a recorded metrics page](../dev/sample-metrics.txt) with drifting values, and Prometheus
and Grafana run with the dashboard provisioned. Grafana picks up a regenerated dashboard within
about 10 s.

```bash
cd dev && docker compose up -d
# http://127.0.0.1:13000/d/flexit-wh4 (no login)
```

A headless screenshot is a quick way to check the result:

```bash
google-chrome --headless=new --hide-scrollbars --window-size=1600,4200 --virtual-time-budget=20000 \
  --screenshot=/tmp/shot.png "http://127.0.0.1:13000/d/flexit-wh4/x?orgId=1&from=now-30m&to=now&kiosk"
```

The bind mounts use `:z` for SELinux (Fedora). It is ignored elsewhere. The Dockerfiles use
`COPY --chmod=644` so files with restrictive modes still work in the container.
